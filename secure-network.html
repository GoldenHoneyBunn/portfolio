CASE STUDY 01 / NETWORKING

Building & Troubleshooting a Segmented Network

Virtualized infrastructure and a documented gateway troubleshooting scenario from Career Simulation 1.

VirtualBoxpfSenseLinuxNmapWiresharkFTP
Scope: Supervised QuickStart training simulation with preconfigured virtual machines—not a real customer network.

Objective

Build and validate a virtualized network with a router/firewall, CEO workstation, DNS server, web server and Kali Linux hosts. The scenario called for segmentation between trusted, untrusted and DMZ networks, while limiting physical hardware requirements.

Problem & diagnosis

The CEO workstation could not reach resources as intended. I documented the environment and identified an incorrect default gateway configuration. I verified the routing and addressing information before correcting the workstation network settings.

Security validation

The project also involved Nmap scans of lab servers, a test FTP transfer observed in Wireshark, account creation, and firewall rules intended to isolate trusted systems from the untrusted segment. Scans showed numerous services on the training web server, making unnecessary service exposure an obvious hardening priority.

What I would improve

  • Use centrally managed DHCP for workstations when appropriate while retaining stable server addressing.
  • Disable legacy or unnecessary services and replace plaintext FTP with a secure alternative.
  • Audit firewall rules against explicit network trust boundaries and apply least privilege.
  • Replace default credentials and avoid placing sensitive data in unprotected files.
