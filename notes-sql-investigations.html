Using SQL Filters for Login Investigations

Applying SQL predicates to identify suspicious sign-in activity and retrieve relevant employee data.

Objective

Practice extracting security-relevant records from login and employee tables with AND, OR, NOT LIKE and comparison operators.

Example: after-hours failed logins

SELECT * FROM log_in_attempts
WHERE login_time > '18:00'
AND success = 0;

Example: two dates

SELECT * FROM log_in_attempts
WHERE login_date = '2022-05-08'
OR login_date = '2022-05-09';

Security relevance

Filtering improves triage by narrowing large datasets to relevant events, such as failed login activity outside expected working hours. Other exercises isolated geographic login patterns and employee groups affected by a security update.
